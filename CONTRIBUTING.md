# Contributing to Hybrids

Thanks for your interest in improving **Hybrids**! This guide explains how to set up the project
locally, run its checks, and submit a change. By participating you agree to follow our
[Code of Conduct](CODE_OF_CONDUCT.md).

## Requirements

- [Node.js](https://nodejs.org) **18 or newer** (see `engines` in [`package.json`](package.json))
- npm — the repository ships a [`package-lock.json`](package-lock.json)
- Git

## Getting started

1. [Fork](https://github.com/hybridsjs/hybrids/fork) the repository and clone your fork:

   ```bash
   git clone https://github.com/<your-username>/hybrids.git
   cd hybrids
   ```

2. Install dependencies:

   ```bash
   npm install
   ```

3. Download the browsers used by the browser test suite (Firefox and WebKit through Playwright):

   ```bash
   npm run test:setup
   ```

   A local Chrome installation is also required, because the same suite runs in Chrome headless.

## Repository layout

| Path | Description |
|---|---|
| `src/` | Framework source — plain ES modules, there is **no build step** |
| `test/spec/` | Browser test specs (Karma + Jasmine), one file per feature |
| `test/types/` | TypeScript type tests, compiled with `tsc --noEmit` |
| `types/index.d.ts` | Public TypeScript declarations |
| `cli/` | The `hybrids` CLI (`hybrids extract`), tested by `cli/test.js` |
| `docs/` | Documentation site built with [docsify](https://docsify.js.org) |
| `.github/workflows/test.yml` | CI workflow (`Test`) that runs on every pull request |

## Everyday commands

| Command | What it does |
|---|---|
| `npm run dev` | Karma in watch mode against Chrome headless (fast feedback loop) |
| `npm run lint` | ESLint over `src`, `test` and `cli` |
| `npm run format` | Prettier write over `src`, `test`, `cli` and `types` |
| `npm run test:cli` | CLI tests only |
| `npm run test:typescript` | TypeScript type tests only |
| `npm run karma` | Full browser test suite (WebKit, Chrome, Firefox headless) |
| `npm run test:coverage` | Coverage run in Chrome headless, writes `coverage/lcov/lcov.info` |

The full suite runs the same checks as CI:

```bash
npm test
```

Run a single browser if WebKit/Firefox are not set up locally:

```bash
npm run karma -- --browsers ChromeHeadless
```

## Documentation

The documentation is a docsify site living in [`docs/`](docs/): every page is a regular Markdown
file, navigation is defined in [`docs/_sidebar.md`](docs/_sidebar.md) and the top bar in
[`docs/_navbar.md`](docs/_navbar.md). To add a page, create the Markdown file under `docs/` and
register it in the sidebar. Because docsify renders Markdown in the browser, the site can be
previewed from any static file server pointed at the `docs/` directory.

Please do **not** edit `CHANGELOG.md` (a symlink to `docs/CHANGELOG.md`) by hand — it is
generated by `standard-version` during releases.

## Commit messages

The project follows [Conventional Commits](https://www.conventionalcommits.org/), as in the
existing history, for example:

```text
fix(template): correct table-mode detection for closed table elements
feat(router): add navigate() method for programmatic navigation
docs: clarify loose option effect on list method invalidation
chore(release): 9.2.1
```

Keep the subject in the imperative mood and focused on a single topic.

## Submitting a pull request

1. Create a branch from `main` in your fork (do not work directly on `main`).
2. Keep the change focused — one topic per pull request — and add or update tests when you fix a
   bug or add a feature. Documentation-only changes are welcome as well.
3. Run the relevant checks locally and include the commands and their results in the pull request
   description:

   ```bash
   npm test
   ```

4. Open the pull request against `hybridsjs/hybrids:main` and describe **what** changed and
   **why**. Link related issues (for example `Closes #284`).
5. CI runs `npm install`, `npm run test:setup` and `npm test` (plus a coverage upload). Please fix
   any failures before requesting a review.
6. Formatting is enforced by Prettier through ESLint, so running `npm run format` and
   `npm run lint` before pushing keeps the diff clean.

## Release process

Releases are cut by the maintainers with [standard-version](https://github.com/conventional-changelog/standard-version):

```bash
npm run release
```

The command runs the full test suite, bumps the version, updates `docs/CHANGELOG.md` and creates
the release commit and tag. Contributors do not need to run it.

## Getting help

- Open an [issue](https://github.com/hybridsjs/hybrids/issues/new) for bugs, feature requests or
  questions.
- Join the [Gitter](https://gitter.im/hybridsjs/hybrids) channel for a quick chat.
